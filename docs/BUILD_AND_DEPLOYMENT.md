# Build and release guide

Installing and running a server is covered in [`PRODUCTION.md`](../PRODUCTION.md). This guide is for whoever builds releases.

## Toolchain

- Node.js 22.12+ (`.nvmrc`: 22), npm 10+, `engine-strict` on. Dependencies are pinned by `package-lock.json`; always `npm ci`.
- Electron is pinned to an exact version in `package.json` (currently 44.5.1, which bundles Node 24); upgrades are deliberate
  (Dependabot ignores Electron major bumps).
- Nothing in the build or at runtime fetches fonts, scripts or styles from the network.

## Scripts

| Script                              | Result                                                                                                                                                           |
| ----------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `npm run build:web`                 | `dist/`: Vite build (hashed assets), copies `public/` (service worker, manifest, icons, offline page, fonts).                                                    |
| `npm run build:server`              | `dist-desktop/app.mjs`: esbuild bundle of `app.tsx` **with all dependencies inlined** (only `vite` stays external; it is only loaded by the development server). |
| `npm run build`                     | both. Neither output directory is tracked by git.                                                                                                                |
| `npm start`, `npm run preview`      | run the build / build then run it.                                                                                                                               |
| `npm run desktop`                   | build + Electron development shell.                                                                                                                              |
| `npm run desktop:dir`               | build + unpacked package in `release/` (fast validation of packaging).                                                                                           |
| `npm run desktop:pack`              | build + installers: NSIS and portable (Windows), AppImage and deb (Linux), dmg (macOS).                                                                          |
| `npm run icons`                     | regenerate PWA and desktop icons from `public/atlas-icon.svg` (needs `npm install --no-save @resvg/resvg-js`).                                                   |
| `npm run check`, `npm run test:all` | typecheck + format + tests; the second also builds and runs the acceptance tests.                                                                                |

Each web build embeds an id (`package.json` version plus a timestamp) and registers the service worker as `/sw.js?v=<id>`; the
worker keeps one cache per id and deletes older ones on activation, so an upgrade never serves stale assets.

## Packaging notes (`package.json` → `build`)

- `files`: `electron/**`, `dist/**`, `dist-desktop/**`, `build/**`, `package.json`. Documentation and the duplicate `public/` are
  not shipped. The server bundle is self-contained, so it does not depend on module resolution inside `app.asar`.
- Icons: `build/icon.ico` (Windows), `build/icon.png` (macOS/Linux, 1024 px). They are committed binaries generated by
  `scripts/make-icons.mjs`.
- `npmRebuild: false`: there are no native dependencies. Keep it that way, or revisit the packaging and the self-contained
  bundle.
- `appId` is `ai.arena.atlasworkspace` (placeholder, decision D13). Changing it after the first release breaks upgrades.

## Verification status of packaging

Verified in this repository's CI configuration and tests: the server bundle runs from an empty folder (`tests/acceptance`), the
shell's navigation rules and hardening flags (`tests/server/electron.test.ts`), and the icons render as expected.

**Not verified** where this release was prepared (no Electron binary download, no display): building installers on each OS,
launching the packaged app, code signing and notarisation, auto-update. The CI job `desktop-package` builds an unpacked Linux
package and checks its contents; the rest is the manual check in `PRODUCTION.md` §9.

## Release checklist

1. `npm ci && npm run check && npm run build && npm run test:acceptance` are green on a clean clone (CI does this).
2. `npm audit --omit=dev` has no high or critical findings.
3. Update `CHANGELOG.md`; bump `version` in `package.json` (and `STORE_SCHEMA_VERSION` with a migration + fixture test if the
   data shape changed).
4. Build installers on each target OS (or via CI runners): `npm run desktop:pack`. Sign and notarise if you have certificates.
5. Run the manual desktop check (`PRODUCTION.md` §9) on a clean machine, including upgrading over the previous release with
   real data (the pre-migration backup is the safety net).
6. Publish with `THIRD_PARTY_NOTICES.md` and the Electron/Chromium licence files that electron-builder places in the package.

## CI

`.github/workflows/ci.yml` runs on pushes to `main` and on pull requests: typecheck (server strict, client, tests), Prettier
check, `npm test`, build, acceptance tests, and a production dependency audit; a second job builds an unpacked desktop package
and inspects it. The workflow could not be executed in the environment where it was written; treat the first runs as part of
review. Dependabot (`.github/dependabot.yml`) opens weekly update PRs, grouped for React and the build tooling.
