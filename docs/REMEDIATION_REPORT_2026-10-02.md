## 3. What the second review found wrong with the first pass

The first pass either reported these as fixed or missed them. The second review re-read every multi-part finding against its full audit text and re-tested the table
rows by behaviour. Each item below was real and is now fixed. Items 1 to 4 were also run against the old code to confirm that their tests fail there.

1. **VAL-04** was still open: `PATCH /api/alerts/:id` with an empty body skipped both permission checks, so a Viewer got a 200 and wrote an audit entry. No test existed.
2. **REP-03** was only partly done: "Most active this week" still listed the first four people in directory order with all-time counts; the Projects milestone list was unsorted, included finished items and was silently cut at eight; the activity report used different periods from the delivery report; "Capacity" still read as a measurement. The ranking is a per-person statistic, so it now follows the same visibility rule as the activity report.
3. **VAL-03**: an unknown `userId` on the activity report still returned 200 ("Selected user").
4. **MIN-03**: the 1.4 MB of PDF fonts were fetched and re-encoded on every export and a font failure was swallowed, so Arabic or Hebrew could print wrongly without a word.
5. **MIN-05 / UX-08 / GOV-02 / DOC-01**: the milestone month was still a bare number; "Invite person" only creates a profile; nothing told staff who can see their updates; three reference documents still claimed local-first, offline and per-export templates.
6. **DATA-03**: CLI commands swallowed configuration warnings, so a mistyped `ATLAS_BACKUP_RETENTION` was safe but silent.
7. **Traceability**: several test titles and three changelog bullets used finding IDs that do not match the audit (for example `SEC-08` for user-administration guards, `SEC-12` for exports). Corrected.
8. **Test infrastructure**: a build that did not know a CLI command made the acceptance helper hang forever; commands now time out.
9. Smaller: dead CSS (`.upgrade-card`, `.desktop-mode-bar`) removed; SEC-11 gained an explicit "plaintext is never accepted" assertion.

Everything else on the P0 and P1 list held up under the checks in section 2.

## 5. Where this release deliberately differs from the audit's recommendations

| Recommendation                                                  | What was done instead, and why                                                                                                                                                                                                                                       |
| --------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| SEC-02: move the default data directory out of the project root | Kept `<app root>/data` so that existing installs keep working; it is now unreachable over HTTP (dev allow-list, production serves only `dist/`). The desktop app already uses the OS user-data directory. An explicit `ATLAS_DATA_DIR` is recommended in production. |
| DATA-07: require `ATLAS_DATA_DIR` in production                 | Not required: it would break `npm start` for first-time users. | SEC-09: never serve demo passwords                              | Production never does. | SEC-07: server-side exports                                     | Exports are generated in the browser; the server checks the permission and audits the export first. ## 6. Remaining risks and limits

- **Scale:** a single JSON file in one process. Comfortable to about 10,000 tasks; slower beyond (measured to 50,000: 1.0 s page load, 415 ms per write). Last write wins when two people edit the same record.
- **Single machine:** backups sit beside the store until someone copies them away; nothing is encrypted at rest.
- **Not seen running:** the Electron window, installers, Windows and macOS. Unsigned builds will trigger SmartScreen and Gatekeeper.
- **Accessibility and language:** no assistive-technology or real-browser test, and no automated colour-contrast check; ar/fa/he text and 123 untranslated strings need native review.
- **Identity and exposure:** local passwords only; no SSO, MFA or e-mail recovery. Keep Atlas on loopback, or behind HTTPS on a private network or VPN; public-internet exposure is not supported (D10).
- **People analytics:** restricted by default and free of invented numbers, but a lawful purpose, notice, retention and an erasure procedure are the organisation's to define (D2, D3).
